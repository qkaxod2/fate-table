# 기동형 페이트 전용 TRPG 툴: 기능과 구현 기획 (v3, 디자인 스레드와 합의 완료)

> 담당: 기능 목록과 구현 형식. 디자인/UX는 "디자인과 사용자 경험 기획" 스레드 담당.
> 용어는 [glossary.md](glossary.md)의 입문자용 명사 표기로 확정. 상세 아키텍처는 [architecture.md](architecture.md).

## 0. 규칙 요약 (툴이 자동화할 대상)

| 요소 | 내용 | 툴에서 할 일 |
|---|---|---|
| 주사위 | 페이트 주사위 4개(4dF, 각 −/0/+) 합 −4~+4 | 3D 물리 주사위(GPU) 또는 눈이 바뀌는 가벼운 연출 중 사용자가 선택 + 결과 즉시 합산 |
| 등급표 | +8 전설 … +3 양호, +2 준수, +1 보통, 0 평범, −1 미흡, −2 최악 | 결과를 등급표 단어로 표시 |
| 접근법 6종 | 신중·지략·화려·완력·신속·은밀 (보통 +3/+2/+2/+1/+1/+0) | 굴림 시 접근법 선택 → 보너스 자동 적용 |
| 행동 4종 | 극복, 이점 창출, 공격, 방어 | 행동 선택 → 결과 해석 자동 |
| 결과 4종 | 실패 / 동점 / 성공 / 대성공(차이 3 이상) | 난이도·상대 굴림과 비교해 판정, 대성공 시 보너스 안내 |
| 특성 | 핵심 컨셉, 약점, 그 외 특성, 상황 특성, 결과로 생긴 특성, 부스트(무료 발동 1회 후 소멸) | 특성 카드(공통 엔티티), 무료 발동 토큰, 부스트 자동 소멸 |
| 발동/강요 | 운명점 1 → +2 또는 재굴림 / 강요 수락 시 점수 획득 | 원클릭 발동, GM 강요 제안 → 플레이어 수락/거부(1점 지불) |
| 운명점 | 재충전(기본 3), 특기 4개 이상이면 재충전 감소 | 실시간 경제 패널, 세션 시작 시 자동 재충전 |
| 특기 | "~할 때 +2" 또는 "세션당 1회 ~" 형식, 기본 3개 | 조건부 보너스 자동 제안 |
| 스트레스 | 칸 3개(1·2·3) | 피해 흡수 계산 보조 |
| 후유증 | 경상 2 / 중상 4 / 중태 6 | 피해 분배 계산기, 회복 시간 추적 |
| 갈등 진행 | 순서는 접근법(신중/신속)으로, 라운드 단위 진행, 양보/퇴장 | 턴 트래커, 양보 처리 |
| 구역 | 장면을 몇 개의 구역으로 나누어 이동 | 간단한 구역 맵(격자 전투맵 아님) |
| 성장 | 이정표(소·중·대) | 이정표 체크리스트와 변경 이력 |

핵심 판단: 기동형 페이트는 "숫자보다 서술"이라서 범용 툴(Roll20 등)의 격자·HP 중심 UI는 맞지 않습니다. 이 툴의 차별점은 **특성과 운명점 경제를 화면의 중심에 두는 것**입니다.

## 1. 기능 목록 (우선순위)

### P0: 없으면 플레이가 안 되는 것 (MVP)
1. **캐릭터 시트**: 접근법 분배 검증(+3/+2/+2/+1/+1/+0), 특성 5칸, 특기·재충전 연동, 스트레스·후유증. 생성 마법사(핵심 컨셉 → 약점 → 접근법 → 특기 순).
2. **판정 굴림**: 행동 + 접근법 선택 → 4dF → 결과 해석(등급표 단어, 차이, 4가지 결과)까지 한 번에. 굴림 직후 "특성 발동으로 +2?" 제안 → 성공으로 바뀌는지 미리보기.
3. **특성 보드**: 장면의 상황 특성, 캐릭터 특성, 결과 특성을 한 곳에. 무료 발동 토큰 표시, 드래그로 발동.
4. **운명점 경제**: 모두에게 보이는 점수 표시, 발동/강요/양보/세션 재충전 자동 기록. GM 풀 별도.
5. **강요 플로우**: GM이 특성을 골라 강요 카드 발송 → 플레이어 수락(+1) 또는 거부(−1).
6. **실시간 세션**: 방 링크로 입장, 채팅 + 굴림 로그 + 상태 동기화, 재접속 시 상태 복구.

7. **피해 흡수 도우미**(디자인 스레드 제안으로 MVP 승격): 공격 성공 시 피해량 → 스트레스/후유증 조합 제안, 불가 시 패배·양보 선택. 양보 시 운명점 보상 자동 처리.
8. **반대 굴림 동시 공개**: 공격자 굴림 후 방어자에게 요청 → 방어자 굴림 완료 시 두 결과를 동시에 공개.
9. **샘플 캐릭터 4명 + 원샷 시나리오**: "5분 안에 첫 굴림".

### P1: 있으면 확실히 편해지는 것
7b. **갈등 트래커**: 참가자 순서, 라운드 단위 진행, 공격 → 방어 자동 연결.
8. **경합·도전 모드**: 경합(먼저 3승)과 도전(여러 극복 굴림) 진행표.
9. **구역 맵**: 구역 상자 + 연결선 + 토큰, 구역마다 상황 특성 부착. 격자 아님.
10. **GM 도구**: NPC 빠른 생성(특성 1~2개 + 잘함/못함), 장면 준비, 강요 아이디어 메모, 이정표 지급.
11. **세션 기록**: 굴림·발동·강요 타임라인 자동 저장, 세션 요약 내보내기(마크다운).

### P2: NAI/ElevenLabs로 몰입감 올리기
12. **NAI 캐릭터 초상화**: 핵심 컨셉·특성 텍스트 → 태그 프롬프트 초안 → 사용자 수정 → 생성(후보 4장) → 시트·토큰에 적용.
13. **NAI 장면 일러스트**: GM이 장면 특성으로 배경 생성, 세션 화면 배경으로 표시.
14. **NAI 특성 카드 아트**(선택): 특성 카드에 작은 일러스트.
15. **ElevenLabs 효과음 (기본)**: 주사위, 대성공, 강요 수락, 후유증 등 10종을 미리 생성해 정적 파일로.
16. **ElevenLabs 맞춤 효과음**: GM이 설명을 적어 장면용 효과음·앰비언트 루프 생성, 버튼으로 모두에게 재생.
(음성 읽기·NPC 목소리는 사용자 결정으로 제외)

### P3: 이후
19. 캠페인 관리(여러 세션, 이정표 누적, 캐릭터 변경 이력)
20. 다른 페이트 계열 지원 확장(페이트 코어 기능 모드)은 범위 밖으로 두고, 필요할 때만 검토
21. 디스코드 연동(굴림 결과 전송)

## 2. 구현 형식

### 플랫폼
**웹앱(PWA)**: 설치 없이 링크로 입장하는 것이 TRPG 툴의 가장 큰 진입장벽 해소. 데스크톱 우선, 태블릿/모바일은 플레이어 시트·굴림 위주로 대응.

### 스택 (추천)
- 프런트: **Next.js(App Router) + TypeScript + React**, 스타일은 Tailwind + 디자인 토큰(디자인 스레드와 합의), 애니메이션 Framer Motion, 주사위 연출은 사용자가 선택: 3D 물리 주사위(three.js + Rapier, 사용자 GPU) 또는 눈이 실시간으로 바뀌는 가벼운 연출. 자동 모드는 기기 성능을 보고 고르며, 서버가 정한 결과에 맞춰 멈춤(architecture.md 5-2절).
- 실시간·DB·인증·저장소: **Supabase** (Postgres, Realtime 채널, Auth, Storage). 소규모 팀이 백엔드 없이 시작하기 좋고, 생성 이미지·효과음 파일 저장까지 한 곳에서.
- 서버 기능: Next.js Route Handler(또는 Supabase Edge Function)로 **NAI·ElevenLabs 프록시**. API 키는 절대 클라이언트로 내려보내지 않음.
- 배포: Vercel + Supabase.

### 아키텍처
```
[브라우저: React UI]
   │ 행동(이벤트) 전송          ▲ 상태 구독
   ▼                           │
[세션 이벤트 로그 (Postgres)] → [rules-engine (순수 TS)] → 파생 상태
   │
[미디어 프록시 API] → NAI / ElevenLabs → Storage 캐시
```
- **rules-engine 패키지 분리**: 굴림 해석, 피해 분배, 운명점 계산을 UI와 무관한 순수 함수로. 테스트가 쉽고 규칙 오류를 막음.
- **주사위는 서버에서 굴림**: 클라이언트는 "굴리겠다" 이벤트만 보내고, 서버(Edge Function)가 4dF를 생성해 이벤트로 기록. 조작 방지 + 모든 화면이 같은 결과로 같은 애니메이션을 재생. 반대 굴림은 양쪽 결과가 모일 때까지 `pending_reveal` 상태로 숨겼다가 한 번에 브로드캐스트.
- **애니메이션은 이벤트에 반응**: 운명점 이동·발동 연출은 Realtime으로 받은 이벤트를 보고 각 클라이언트가 재생. 별도 동기화 불필요, 늦게 들어온 사람은 애니 없이 최종 상태만.
- **이벤트 소싱**: "굴림함", "특성 발동함", "강요 수락함" 같은 이벤트를 쌓고 상태는 그로부터 계산. 세션 기록·되돌리기·재접속 복구가 공짜로 따라옴.
- **권한**: GM / 플레이어 / 관전자. 숨긴 특성, GM 메모는 GM만.
- **미디어 생성 큐**: `media_jobs` 테이블(pending → running → done/failed). 서버 프록시가 작업을 처리하고 완료 시 Realtime으로 알림 → UI는 백그라운드 생성 + 완료 알림(디자인 스레드 원칙과 일치). NAI는 동시 생성 제한이 있어 키당 직렬 처리.
- **미디어 비용 관리**: 방(캠페인)별 생성 한도, 같은 프롬프트 결과 캐시, 생성 전 확인 단계, 효과음은 미리 생성해 정적 파일로.

### 데이터 모델 (핵심)
`Campaign`, `Session`, `Character`(approaches, aspects[], stunts[], refresh, fatePoints, stress[3], consequences{mild,moderate,severe}), `Scene`(situationAspects[], zones[]), `Aspect`(text, kind: highConcept/trouble/normal/situation/consequence/boost, ownerType: character/scene/zone, ownerId, freeInvokes, hidden). 캐릭터·장면·구역 특성을 **하나의 테이블·하나의 카드 컴포넌트**로 다룸, `Event`(type, actor, payload, createdAt), `MediaAsset`(kind: portrait/scene/voice/sfx, prompt, url).

## 3. 단계별 로드맵
| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 0. 기반 (1주) | 저장소, 디자인 토큰, rules-engine 골격과 테스트 | 굴림 해석 테스트 통과 |
| 1. MVP (4주) | P0 전체(생성 위저드, 굴림+발동 트레이, 특성 카드, 운명점, 강요, 피해 흡수, 실시간 방, 로그, 샘플 원샷) | 실제 1세션을 이 툴만으로 완주 |
| 2. GM·NAI (3~4주) | 갈등 트래커, GM 서랍, 구역 보드, NAI 초상화/배경 | 갈등 장면을 계산 없이 진행 |
| 3. 효과음·공유 (2주) | ElevenLabs 기본·맞춤 효과음, 리플레이 내보내기, 테마 프리셋 | 비용 한도 안에서 안정 동작 |
| 4. 다듬기 | 캠페인, 모바일 최적화, 운명점 흐름 그래프, 테이블 모드(큰 화면은 장면+로그, 조작은 각자 폰) | 외부 플레이 테스트 만족도 수집 |

## 4. 만족도를 위한 기능 원칙
- **규칙은 몰라도 굴릴 수 있게**: 굴림 버튼이 행동·접근법·결과 해석까지 안내. 초보도 "대성공이면 뭘 얻지?"를 화면에서 바로 확인.
- **운명점 사용을 부추기기**: 실패 직후 "이 특성을 발동하면 성공" 제안. 페이트의 재미는 점수를 쓰고 받는 순환이라서.
- **GM 부담 줄이기**: 강요 카드, NPC 빠른 생성, 자동 기록.
- **미디어는 선택**: NAI·ElevenLabs가 없어도 완전히 플레이 가능. 켜면 몰입감이 더해지는 구조.
