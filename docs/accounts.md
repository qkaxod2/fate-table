# 계정

처음 들어온 사람은 익명 세션으로 바로 놀 수 있어요. **계정**(`/account/`)에서 이메일이나 구글을 연결하면, 같은 사용자 그대로 정식 계정이 되어 내가 들어간 방과 저장한 캐릭터가 다른 기기에서도 보여요.

```
익명으로 놀던 중 ── 계정 만들기(이메일) / 구글 연결 ──▶ 같은 user id가 정식 계정이 된다 (옮길 것 없음)
익명으로 놀던 중 ── 이미 있는 계정으로 로그인 ──────▶ account 함수가 익명 기록을 계정으로 옮기고 익명 사용자를 지운다
```

- 옮기기(`merge_users`): 방 참가 자리, 방장(`rooms.created_by`), 이벤트에 적힌 사용자 id(행동한 사람·캐릭터 주인·비공개 이벤트 주인), 봉인 주사위, 캐릭터 보관함, 그림 사용량. 둘 다 들어가 있던 방은 계정 쪽 자리를 남기고, 익명 쪽이 GM이었으면 GM을 넘겨받는다.
- 캐릭터 보관함(`saved_characters`): 캐릭터 만들기에서 저장하면 이 브라우저와 함께 계정(익명 포함)에도 올라간다. 방의 **캐릭터 데려오기**는 둘을 합쳐 보여 준다. 로그인하면 이 브라우저에만 있던 캐릭터도 올린다.
- 기본 닉네임: 계정 화면에서 정하면 방 만들기·참가 화면에 미리 채워진다 (`user_metadata.nickname`).
- 로그아웃하면 이 브라우저에 남은 캐릭터·방 기록·닉네임을 지운다 (계정에 올라가 있으니).

## 설정

`Supabase` 워크플로가 배포 때 Management API로 로그인 설정을 맞춘다: 익명 로그인, 이메일 로그인, 수동 연결(익명 → 구글), 사이트 주소와 돌아올 주소(`https://<owner>.github.io/<repo>/**`, `http://localhost:3000/**`).

| 이름                         | 종류     | 설명                                                                                                      |
| ---------------------------- | -------- | --------------------------------------------------------------------------------------------------------- |
| `AUTH_EMAIL_CONFIRM`         | variable | `true`면 가입할 때 확인 메일을 보낸다. Supabase 기본 메일 서버는 팀원에게만 보내지므로 SMTP를 붙인 뒤에만 |
| `GOOGLE_OAUTH_CLIENT_ID`     | variable | 구글 로그인 (둘 다 있을 때만 켠다)                                                                        |
| `GOOGLE_OAUTH_CLIENT_SECRET` | secret   | 〃                                                                                                        |

구글 OAuth 클라이언트는 Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID(웹 애플리케이션)에서 만들고, 승인된 리디렉션 URI에 `https://<project-ref>.supabase.co/auth/v1/callback`을 넣는다. 구글 버튼은 서버에서 켜져 있을 때만 보인다 (`/auth/v1/settings`).
