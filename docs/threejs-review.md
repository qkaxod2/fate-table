# Three.js로 키울 수 있는 곳 (2026-11-25 점검)

`threejs-game-director` 스킬 기준으로 지금 화면을 훑고, Three.js가 값을 하는 곳과 안 하는 곳을 나눴어요.
기준은 하나예요. **결과를 더 잘 읽히게 하거나, 굴림의 손맛을 키우는 곳에만 쓴다.** 장식으로 떠다니는 3D는 `ai-slop` 가이드(떠다니는 도형, 상태를 알려 주지 않는 움직임)에 걸려요.

## 비용

- `three` 본체는 압축 후 약 170KB(이번 빌드에서 잰 값, 압축 전 680KB)예요. 정적 내보내기라 첫 화면 번들에 넣으면 안 되고, 필요한 화면에서 `import('three')`로 따로 받아야 해요. 시험판도 그렇게 했어요.
- 한 화면에 WebGL 캔버스는 하나만 두는 게 좋아요. 휴대폰 브라우저는 컨텍스트를 8~16개쯤에서 끊어요.
- 움직임 줄이기 설정이면 3D 연출 없이 결과 자세만 그려요. WebGL이 없으면 지금 CSS 판으로 돌아가요.

## 1번 시험판에서 한 것

- `src/components/roll/DiceGL.tsx`: `Dice3D`와 같은 약속(`dice`, `rollKey`, `tone`, `onSettled`).
  - 물리 엔진 없이 정해진 궤적(떨어짐 → 두 번 튀김 → 미끄러짐). 회전은 끝 자세에서 거꾸로 감아 둔 만큼 풀리는 방식이라, 마지막 자세가 정확히 결과 면이에요. 모두에게 같은 모양으로 굴러요.
  - 윗면이 −일 때 막대가 세로로 서서 `I`처럼 읽히지 않게, 막대가 화면 가로로 눕는 방향으로 돌려 놓아요.
  - 처음 닿을 때 지금과 같은 `dice-settle` 소리와 진동.
  - 내 주사위(상아에 먹 눈) · 상대 주사위(먹에 상아 눈) 색은 토큰에서 읽어요.
- `/lab/dice/`: 같은 굴림을 지금 CSS 주사위와 나란히 굴려 보는 화면. 메뉴에는 걸지 않았어요.

## 1번을 진짜로 넣으려면

1. `DiceTray`에서 WebGL이 되고 움직임 줄이기가 꺼져 있을 때만 `DiceGL`을 쓰고, 아니면 `Dice3D`.
2. 판정 카드(`CheckCard`)는 주사위 자리가 작아요. 카메라를 더 위에서 내려다보게 하고, 판 크기를 주사위 줄에 맞춰요.
3. 서버를 기다리는 동안의 `TumblingDice`도 같은 캔버스에서 굴려야 결과가 와도 장면이 끊기지 않아요.
4. 휴대폰 실기기에서 프레임과 발열을 재요. 이 컨테이너는 소프트웨어 렌더러라 프레임 수치는 믿을 수 없어요.
